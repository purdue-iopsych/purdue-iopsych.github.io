# purdueiopsych.com

The website for the **Purdue University Industrial-Organizational Psychology**
Ph.D. program, in the Department of Psychological Sciences at West Lafayette.

Live site: <https://www.purdueiopsych.com>

It is a plain static site — hand-written HTML and CSS, generated by one small
Node script. No framework, no dependencies, no npm install. If you can edit a
text file, you can edit this site.

## Making a change

```bash
# 1. edit the content
#      src/*.html   page text
#      data/*.json  people, alumni, news, newsletters
# 2. rebuild
node build.js
# 3. publish
git add -A && git commit -m "Update people page" && git push
```

GitHub Pages redeploys automatically from `main`, usually within a minute.

> **Always run `node build.js` before committing.** The `.html` files at the repo
> root are generated. Editing them by hand does nothing — the next build
> overwrites them.

## What's where

```
src/            page content (the inside of <main>) — edit these
data/           people, alumni, news, newsletters, interviews — edit these
build.js        the generator
css/style.css   the whole stylesheet
images/         photographs and headshots
docs/           program PDFs (UN Global Compact report, application guides)
newsletters/    the PAGSIP newsletter archive, 1952-present
scripts/        one-off tools from the Google Sites migration
```

Everything else at the repo root (`index.html`, `people/`, `sitemap.xml`, …) is
build output.

## Preview before you publish

```bash
npx serve .
```

Open <http://localhost:3000>. A local server is required — opening the files
directly with `file://` breaks the CSS and image paths.

## Deployment

GitHub Pages, deploying from the `main` branch, repo root. `.nojekyll` disables
Jekyll processing; `CNAME` holds the custom domain.

## Notes

- **URLs are deliberately unchanged** from the previous Google Sites version,
  including the long PAGSIP path, so existing links keep working.
- Page content came from the program's own pages. Please don't add facts,
  figures, or dates that aren't sourced from the program.

`CLAUDE.md` holds the same workflow in more detail, plus the list of open TODOs.
